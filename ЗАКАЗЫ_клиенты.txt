ФАЗА 2 (ЗАКАЗЫ/КАССА, клиенты): order_views.py — по филиалам
=============================================================
Клиент «принадлежит» филиалу, если у него есть заказ в этом филиале.
Правило = назначенные филиалы пользователя (user_location_ids). Требует Фазу 1.

Из корня проекта, командой tar:

    tar xzf ~/Downloads/fc_branch_p2_customers.tgz -C .
    python apply_branch_phase2_customers.py
    python manage.py test foodcost.tests.test_branch_customers

Что сужается (ВИДИМОСТЬ):
  • customer_list   — показываются только клиенты с заказом в филиалах
                      пользователя; KPI (всего/новые/проблемные/повторные/VIP)
                      по тем же клиентам;
  • customer_detail — карточка чужого клиента недоступна (redirect на список).

Намеренно НЕ сужены (чтобы не лезть в твой рефактор клиентов и не трогать
инвазивные агрегаты):
  • суммы по клиенту в списке (total_spent / средний чек) — остаются по всем
    филиалам. Нужно «суммы только по моему филиалу» — скажи, сделаю отдельно;
  • customer_lookup (подстановка по телефону при создании заказа) — не сужаем:
    это помощник ввода, дедуп всё равно идёт через get_or_create(country, phone),
    а сужение ломало бы подстановку для только что заведённых клиентов без заказов.

Супер-админ / без филиалов видят всех. Миграций нет. Идемпотентно.
Якоря общие для старой и новой версий customer_list/customer_detail — патч
работает и до, и после твоего рефактора. Если функция в файле задвоена
(старая+новая рядом) — скрипт не тронет и попросит убрать дубль.
